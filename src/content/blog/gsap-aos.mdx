Inspired by the first animation library I ever used, [AOS](https://michalsnik.github.io/aos/) by michalsnik, I wanted to bring that same HTML-first simplicity to the powerhouse that is GSAP. 

The result is **gsapAos**. One small script that parses data-attributes and handles all the [ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/) and timeline logic automatically.

## The core concept

Under the hood, the library relies on a simple dictionary of animations. To create a new animation, you don't write timeline logic, you just define an `origin` (where it starts) and a `destination` (where it ends). Same concept as [gsap.fromTo](https://gsap.com/docs/v3/GSAP/gsap.fromTo()/).

This is an example of how the animations dictionary looks like:

```javascript frame="terminal" title=fade.js {3-5, 7-9}
export default {
    "fade-up": {
        origin: {
            opacity: 0,
            y: 20,
        },
        destination: {
            opacity: 1,
            y: 0,
        },
    },
    "fade-up-blur": {
            // ...
        },
    },
};
```

Once your dictionary is set up, you never have to write JS for a basic reveal animation again. You just apply HTML attributes.

## The simplest case

Apply `data-aos` to an element, specify an animation from the dictionary as its value, and it will trigger as soon as it enters the viewport.

```html 'data-aos="fade"'
<div class="grid">
    <div class="square" data-aos="fade"></div>
    <div class="square" data-aos="scale-out-fade"></div>
    <div class="square" data-aos="fade-left-blur"></div>
    <div class="square" data-aos="rotate-360"></div>
</div>
```

## Groups and staggering

Animating a single element is rare. A row of cards or a heading-and-subheading pair is much more common, `data-aos-group` is built exactly for this.

When applied to a parent, its children will animate in sequence, inheriting the group's animation key and staggering automatically.

```html {3}
<div
    class="grid"
    data-aos-group="fade-up-blur"
>
    <div class="square"></div>
    <div class="square"></div>
    <div class="square"></div>
    <div class="square"></div>
</div>
```

<div class="spotlight">

        data-aos-debug
    >
        <div class="square"></div>
        <div class="square"></div>
        <div class="square"></div>
        <div class="square"></div>
    </div>
</div>

### Targeting descendants and overrides

When using `data-aos-group`, the library operates on one of two paths:

1. **Automatic direct children.** If you only define the group (like in the previous example), the script automatically targets all direct children. This is perfect for simple grids or lists.

2. **Explicit targeting.** If your layout is more complex—say you need to animate deeply nested elements or override specific animations—you can explicitly mark elements using the `data-aos-child` attribute.

```html 'fade-up-blur' 'split-'
<div
    class="grid"
    data-aos-group="fade-up-blur"
>
    <!-- Inherits the group animation fade-up-blur -->
    <div class="rectangle" data-aos-child>
        <!-- Forces a specific animation within the group timeline -->
        <p data-aos-child="split-up-chromatic">Si vis pacem...</p>
    </div>
    
    <div class="rectangle" data-aos-child>
        <p data-aos-child="split-left">Si vis pacem...</p>
    </div>
    
    <!-- Ignored from the explicit group timeline -->
    <div class="rectangle opacity-25"></div>
    
    <div class="rectangle" data-aos-child>
        <p data-aos-child="split-up">Si vis pacem...</p>
    </div>
</div>
```

<div class="spotlight mb-5">
    <div 
        class="grid grid-cols-2 gap-5"
        data-aos-group="fade-up-blur"
        data-aos-stagger-gap="900"
        data-aos-duration="1200"
        data-aos-debug
    >
        <div class="bg-iron-800 rounded-lg p-5" data-aos-child>
            <p class="text-lg" data-aos-child="split-up-chromatic">Si vis pacem, para bellum. Vivamus fringilla dictum porta luctus dignissim tortor conubia semper.</p>
        </div>
        <div class="bg-iron-800 rounded-lg p-5" data-aos-child>
            <p class="text-lg" data-aos-child="split-left">Si vis pacem, para bellum. Vivamus fringilla dictum porta luctus dignissim tortor conubia semper.</p>
        </div>
        <div class="bg-iron-800 rounded-lg opacity-25"></div>
        <div class="bg-iron-800 rounded-lg p-5" data-aos-child>
            <p class="text-lg" data-aos-child="split-up" data-aos-split-mask>Si vis pacem, para bellum. Vivamus fringilla dictum porta luctus dignissim tortor conubia semper.</p>
        </div>
    </div>
</div>

Notice what happens in this timeline sequence:

1. The first rectangle enters via the group default `fade-up-blur`.
2. Its nested paragraph triggers immediately after, explicitly using `split-up-chromatic`.
3. The second rectangle enters `fade-up-blur`, followed by its own paragraph `split-left`.
4. **The third rectangle is completely skipped** because it lacks the `data-aos-child` attribute.
5. The fourth rectangle and its masked text wrap up the timeline.

This two-path system gives you the best of both worlds: absolute zero-config simplicity when you want it, and granular control over nested timelines when you need it.
